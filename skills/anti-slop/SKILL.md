# Style-aware anti-slop

Use [decision rules](../../knowledge/foundations/anti-slop.md).
A familiar treatment is not automatically wrong. Describe the visible symptom and
why it weakens this brief before recommending removal.

Ask whether another product name could replace the current name without changing
the page's substance. If so, inspect factual copy, actual product proof, hierarchy
and art direction. This is a diagnostic prompt, not an automatic failure rule.

Gradients, large type, glows, three-column cards, monochrome, serif type and asymmetry
can all be appropriate. Identify repeated choices without a content reason,
conflicting visual systems, or decoration obscuring the primary task.

Keep functional and accessibility failures separate from taste judgments. A fix
should strengthen the selected direction, not convert every project into restrained
SaaS. Use [critique](../../templates/critique.md) and render after targeted changes.
